# ADR-001: Технологические и архитектурные решения для MVP

## Статус
Принято

## 1. Технологический стек
- **Frontend framework:** React + Vite
- **Язык программирования:** TypeScript (фронт + бэкенд)
- **Система управления состоянием:** Zustand (клиентское UI-состояние) + React Query (серверные данные)
- **Способ работы с серверными данными:** REST API через Vercel Serverless Functions (Node.js), клиент не обращается к Supabase напрямую
- **UI-библиотека / стилизация:** Tailwind CSS + shadcn/ui (или Headless UI)
- **Backend:** Vercel Serverless Functions
- **База данных:** Supabase Free Tier (PostgreSQL + Auth)
- **Система тестирования:** Vitest + React Testing Library + Playwright
- **Инструменты сборки и разработки:** Vite, ESLint, Prettier, GitHub Actions, Vercel Hobby

**Плюсы:** бесплатный старт без привязки платёжной карты, единый язык (TypeScript), простота развёртывания, достаточно мощности для десятков пользователей.
**Минусы:** возможный холодный старт serverless-функций, привязка инфраструктуры к Vercel (код при этом переносим).

## 2. Единая точка доступа к данным
Все запросы клиента к данным проходят через собственные API-функции (`/api/`). Прямого доступа браузера к Supabase нет.

**Обоснование:** полный контроль над бизнес-логикой, централизованная валидация (Zod), простота миграции с Supabase в будущем.
**Альтернатива:** прямой доступ к Supabase из браузера с RLS (быстрее разработка, но меньше контроля).
**Компромисс:** больше кода для поддержки эндпоинтов.

## 3. Управление состоянием
- Серверное состояние — React Query.
- Клиентское UI-состояние — Zustand.
- Сессия аутентификации — Supabase Auth, дублируется в Zustand-сторе `auth`.

**Альтернатива:** MobX (больше бойлерплейта и «магии», избыточно для MVP).
**Компромисс:** Zustand подходит для небольшого и среднего клиентского состояния; при резком усложнении логики может потребоваться пересмотр.

## 4. Лендинг-страница в MVP
Главная страница — лендинг с описанием сервиса и кнопками «Войти» / «Зарегистрироваться».

**Обоснование:** пользователь, переходящий по ссылке, должен видеть визуальный интерфейс с объяснением ценности, а не сразу экран авторизации.
**Компромисс:** увеличивает объём frontend-разработки для MVP.

## 5. Аутентификация
**Рекомендуемое решение:** Supabase Auth.
**Альтернатива:** кастомный JWT в Serverless Functions.
**Статус:** требует финального подтверждения при начале реализации.

## 6. Развёртывание и бесплатный старт
- Фронтенд: Vercel Hobby.
- Бэкенд: Vercel Serverless Functions.
- База данных: Supabase Free Tier.
- Домен: предоставляется Vercel из коробки.

**Ограничение:** Oracle Cloud Always Free отброшен (требует платёжные реквизиты, недоступные резиденту РФ).
