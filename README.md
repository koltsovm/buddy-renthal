# README for vehicles-rental project

# Братский прокат - Совместное владение техникой

## Описание

Веб-приложение для организации совместного использования редко эксплуатируемой техники (мотобайки, лодки, квадроциклы, снегоходы) внутри закрытой группы собственников.

## Структура проекта

```
client/         # React + Vite приложение
api/            # Vercel Serverless Functions
api/auth/       # Аутентификация
api/groups/     # Группы собственников
api/equipment/  # Каталог техники
api/bookings/   # Бронирования
api/expenses/   # Расходы

supabase/       # Миграции и seed SQL
supabase/migrations/
supabase/seed.sql

tests/          # E2E тесты
tests/e2e/
```

## Развертывание

### Локальная разработка

1. Установите PostgreSQL
2. Настройте Supabase (либо локально, либо используйте Supabase Free)
3. Установите переменные окружения из `.env.example`
4. Запустите сервер API:
   ```bash
   npm run dev --workspace=api
   ```

5. Запустите фронтенд:
   ```bash
   npm run dev --workspace=client
   ```

### Развертывание в Vercel

```bash
npm run build
vercel --prod
```

## Архитектурные принципы

1. **Тонкий клиент + серверные функции + управляемая БД**
2. **Нет прямого доступа браузера к Supabase** - все запросы идут через `/api/`
3. **Золотое правило маршрутизации**: Фронтенд никогда не обращается напрямую к Supabase
4. **Разделение ответственности**:
   - Клиент: отображение и ввод
   - API: валидация, бизнес-логика, обращение к Supabase
   - Supabase: хранение, RLS, аутентификация

## Конвенции кодирования

### TypeScript
- Весь код на TypeScript с включенным строгим режимом
- `any` допустим только с объяснением `// TODO`

### React
- Функциональные компоненты + хуки
- Props типизируются через интерфейсы или типы

### Валидация
- Входные данные валидируются через Zod в API-функциях

### Обработка ошибок
- Стандартизированный формат ответов: `{ data: ..., error: ... }`
- HTTP-статусы: 400, 401, 403, 404, 500
